# Handoff: Windows build of PySol Lite

Written 2026-11-21 on the Mac for the Claude session that will run on a
Windows machine after cloning this repo. Read this first, then
`PROGRESS-NOTES.md` (sections 107-112 are the most recent) and `README.md`.

## What this is

PySol Lite is a macOS-first fork of PySolFC (Python 3 + Tkinter/ttk, 276
solitaire games). Version scheme is YY.MM (current 26.11). The macOS app is
built with py2app, signed, notarized and released (v26.11). The user wants to
try compiling the same code for Windows. **Nothing has ever been run on
Windows since the toolkit clean-up**; the Windows paths (`pysollib/winsystems/win32.py`,
`Win32AudioClient` in `pysolaudio.py`) compile and import but are untested.
The user chose to keep Windows/Linux code on purpose; do not strip it.

## Goal

1. Run the game from source on Windows and fix whatever breaks.
2. Package it as a Windows app (PyInstaller or cx_Freeze; py2app is macOS
   only, and `setup_osx.py` must not be used). No packaging exists yet;
   write a spec file and `scripts/build_windows.ps1`.
3. Optionally wrap in an installer (Inno Setup/NSIS) or zip. Code signing is
   optional and a separate cost; unsigned builds trigger SmartScreen.

Keep macOS behaviour unchanged: guard Windows-specific changes with
`sys.platform == 'win32'` or `WIN_SYSTEM == 'win32'`.

## Setup on Windows

- Python 3.14 from python.org (includes Tcl/Tk 9). Python >= 3.10 is the
  minimum in `setup.py`.
- `python -m venv .venv`, then
  `pip install attrs configobj pillow pygame-ce pysol-cards markdown pyinstaller`
  (`accessible-output2` is optional, for screen readers).
- **Cardsets are not in git.** Download `PySolFC-Cardsets--Minimal-3.1.0.tar.xz`
  from the SourceForge PySolFC cardsets page, extract into an empty folder, and
  copy `cardset-standard` and `cardset-uni-mahjongg` into `data/`
  (the Mac copy of `data/` has them already, so copying from there also works).
  `scripts/prune_card_backs.py` trims the backs; the macOS build removes all
  other cardsets.
- **Help pages:** `data/html/rules/*.html` (256 pages) are generated by
  `make rules` and need the `attr` module. On Windows without `make`, copy
  the generated `data/html` from the Mac, or run the Makefile's rules
  command by hand with the venv's Python.
- Run: `python pysol.py`. Check `python pysol.py --version` first.
- Settings live in `~/.pysol` (options.cfg, statistics.dat).

## Things to expect or check

- Theme: `Options.setDefaults` picks `winnative`/`xpnative` on Windows.
- Toolbar images: macOS uses the Phosphor PNGs in `data/images/toolbar/phosphor`
  (`App.getToolbarImagesDir`); check what Windows gets (`bluecurve` was the
  non-Mac fallback in older notes, but the `bluecurve` folder no longer
  exists in `data/images/toolbar`, so this likely needs fixing: use Phosphor
  everywhere or the Windows loader will find no images).
- Window icon: `base_init_root_window` in `pysollib/winsystems/common.py`
  calls `wm iconphoto` from `data/images/icons/*` on every platform except
  macOS (skipped there so the Dock icon does not change after launch). The
  PNGs already contain the new cards logo. **`data/pysol.ico` still has the
  old upstream club icon**; regenerate it from `cards-logo.png` (sizes 16,
  32, 48, 256) for the exe icon.
- Sound: `pygame-ce` mixer; `Win32AudioClient` exists but is untested.
- Help opens in the default browser (untested on Windows).
- Mac-only things to skip: `setup_osx.py`, `scripts/notarize.sh`,
  `scripts/make_dmg.sh`, `scripts/entitlements.plist`, `data/PySol.icns`.
- PyInstaller needs `--add-data` for `data` and for `pysollib` resources, and
  must collect pygame's DLLs and the Tcl/Tk libraries. Test the frozen app,
  not just the source run (a missing data folder is the usual failure).
